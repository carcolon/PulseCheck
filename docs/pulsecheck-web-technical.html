PulseCheck Web · Documentacion tecnica

Este repositorio implementa la experiencia administrativa y el landing de PulseCheck. La aplicacion se construye con React y Vite, se despliega en Azure Static Web App y consume la API del backend para autenticacion, administradores, campañas, dispositivos, actividad y tableros.

1. Objetivo del repositorio

Landing

Explica el posicionamiento del producto, descarga del agente y acceso administrativo.

Backoffice

Permite administrar campañas, usuarios admin, dispositivos, actividad y respuestas.

Tiempo real

Recibe eventos por SignalR y actualiza el panel sin depender solo de refresh manual.

Patron de trabajo

  • React 19 + Vite.
  • Navegacion basada en tabs y rutas del admin.
  • Hooks de sesion y panel separan fetch, estado y tiempo real.
  • GSAP se usa para motion puntual en landing y loaders; no gobierna el estado de datos.
  • Recharts se usa para graficas del dashboard.

4. Rutas y modulos principales

Ruta / modulo Uso Dependencias principales
/ Landing comercial y descarga del agente CTA de descarga con VITE_AGENT_DOWNLOAD_URL, motion GSAP, bloques de producto.
/login Acceso administrativo Login local y flujo Entra ID.
/auth/callback Retorno de Entra Procesa redirect y materializa sesion del panel.
/admin/overview Centro de decisiones operativas /api/dashboard/overview, graficas y alertas.
/admin/campaigns Creacion y edicion de campañas CRUD, preguntas tipo escala, texto y si/no, frecuencia en lenguaje humano.
/admin/agents Inventario de dispositivos Lista de agentes registrados y estado de conexion.
/admin/activity Actividad por usuario/dispositivo Eventos de lock, unlock, suspend y resume en tiempo real.
/admin/responses Insights y exportes Lista de respuestas recientes. Las respuestas de escala muestran valor y rango, por ejemplo 5 en escala 1-10.
/admin/admins Gestion de administradores Lista, crea y elimina admins autorizados para ingreso con Entra ID.

5. Integracion con backend

HTTP

  • Autenticacion y sesion administrativa.
  • Alta y baja de admins Entra autorizados.
  • Consulta y edicion de campañas.
  • Inventario de dispositivos, respuestas, dashboard y exportes.

SignalR

  • Actualiza actividad del agente en tiempo real.
  • Actualiza tablero administrativo sin esperar polling completo.
  • El polling de respaldo sigue existiendo como red de seguridad operativa.
El frontend no calcula semantica sensible de negocio si el backend ya entrega un contrato resuelto. El caso principal es el overview del dashboard, cuya logica de estado se movio al backend para evitar inferencias inconsistentes.

6. Diseno operativo de la experiencia

No tecnico

Las reglas de programacion de campañas se traducen a lenguaje humano en la interfaz; no se expone la sintaxis tecnica cruda al usuario final.

Responsive

Landing, login, shell administrativa y tabs principales ya fueron adaptados para movil y tablet con colapso de columnas y scroll horizontal controlado.

Tiempo real

La vista de actividad del agente se rediseño para mostrar usuarios con actividad detectada, filtros y detalle por usuario en vez de una lista plana de eventos.

7. Variables y despliegue

Variable Uso
VITE_API_BASE_URL Base URL de la API backend.
VITE_AGENT_DOWNLOAD_URL URL publica estable del instalador del agente.
VITE_ENTRA_TENANT_ID, VITE_ENTRA_CLIENT_ID, VITE_ENTRA_API_CLIENT_ID Integracion del login federado con Entra.

El pipeline azure-pipelines-web.yml compila con Node 20 y despliega a Azure Static Web App. La aplicacion se entrega ya construida y no ejecuta server-side rendering.

8. Riesgos y limites vigentes

  • El bundle del frontend sigue siendo grande; la responsividad visual ya se mejoro, pero la carga movil todavia puede beneficiarse de code splitting adicional.
  • La UI depende de contratos consistentes del backend; cuando se introduce un nuevo tipo de dato en API, el web debe acompañarlo para no degradar la experiencia.
  • La vista de actividad usa datos del backend; si un agente no actualiza a la version que reporta telemetria extendida, no aparecera en detalle aunque exista como dispositivo registrado.
